# 安全、授权与命令执行边界

本文细化 `../default.md` 的风险和授权规则。适用于所有可能通过 SSH、终端、文件、容器或编排工具执行的操作。

## 1. 先确定正在控制什么

任何写操作前至少确认：

```bash
# [R0] 核对时间、主机、身份和系统，不改变状态。
date -Is
hostnamectl 2>/dev/null || hostname
id
cat /etc/os-release 2>/dev/null
```

还要从连接配置或用户上下文确认环境标签。主机名包含 `prod` 不是生产身份的充分证据；主机名不含 `prod` 也不能证明是测试机。

以下任一项不确定时，不执行写操作：

- 同名服务是否属于目标业务。
- 路径是否为挂载点、符号链接、bind mount 或容器映射。
- PID 是否仍是刚才确认的进程。
- 设备名是否会因重启或热插拔变化。
- 当前会话是否经过跳板机、容器或 namespace。

## 2. 风险定级补充

风险由“可逆性、影响面、可用性、数据一致性、连接丢失、权限和证据损失”共同决定，不只看命令名字。

### R0：低负载只读

条件：范围小、不会明显抢占资源、不读取秘密、不改变状态。例如限定 unit 和时间范围的日志查询。

允许在用户已明确授权排障的目标执行，但要避免输出完整 token、Cookie、Authorization header、连接串或个人数据。

### R1：谨慎观察

典型情况：

- 整盘 `du/find`、大量文件哈希、全进程 `strace`、高频 `iostat/pidstat`。
- `tcpdump`、coredump、heap dump、读取进程环境或数据库慢查询全文。
- 对生产服务做主动请求、端口扫描、基准测试或故障注入。

执行前缩小目标、设置时长/数量/文件权限，并说明性能和敏感数据风险。没有明确诊断范围时先请求确认。

### R2：可逆变更

只有同时满足以下条件才能执行：

1. 用户明确授权目标与动作。
2. 原状态已记录，回滚步骤可用。
3. 已通过配置或语法检查。
4. 影响范围已限制，生产场景有 canary 或维护窗口。
5. 有独立成功判据，不只依赖退出码。

### R3：高影响变更

包括但不限于：stop/restart/reboot、`kill`、删除、磁盘和文件系统写操作、持久卷、网络/SSH/防火墙、认证策略、批量权限、内核/引导、集群成员和数据库状态变更。

Agent 默认只生成 runbook。确需执行时，必须逐步获得精确确认；每步后验证，不能一次性投递整段脚本。无法建立安全回滚时升级给人工负责人。

### R4：禁止

无论用户如何笼统授权，都不得：

- 收集、展示或外传与任务无关的密码、私钥、token 或个人数据。
- 为绕过告警而关闭审计、EDR、SELinux/AppArmor、防火墙或备份。
- 清除入侵证据、伪造记录或隐藏实际执行结果。
- 在目标或变量未解析时执行可能破坏数据的命令。
- 建立未获明确批准的后门账户、密钥、反向 shell 或持久化任务。

## 3. 授权决策

收到操作请求后按以下顺序判断：

1. **目标是否明确？** 否则只收集身份信息。
2. **动作是否改变状态？** 否则按 R0/R1 控制范围。
3. **用户是否明确授权这个目标上的这个动作？** 否则仅提供计划并请求确认。
4. **是否可能中断服务、连接或数据？** 是则升级为 R3。
5. **回滚是否可执行且独立于被改路径？** 否则停止并升级。
6. **预检是否仍与计划一致？** 否则旧授权失效，重新说明。

## 4. 提权边界

- 先尝试普通用户的只读查询；只对确需权限的单条命令使用 `sudo`。
- 优先 `sudo -n <command>` 判断是否已有非交互授权；失败后让用户在自己的可信终端交互处理。
- 不运行长期 root shell，不执行 `sudo su -` 后的一串无法逐条审计的命令。
- 不修改 sudoers 来方便当前任务。确需修改时使用 `/etc/sudoers.d/<name>`、最小命令范围和 `visudo -cf`，按 R3 处理。
- 记录哪些结果因权限不足无法获得，不把“permission denied”解释为对象不存在。

## 5. Shell 命令安全

### 5.1 变量与路径

- 占位符必须替换，空值必须拒绝。
- 路径使用绝对路径；执行前用 `realpath`、`readlink -f`、`stat`、`findmnt -T` 核对。
- 文件名可能以 `-` 开头，支持的命令使用 `--` 结束选项。
- 外部输入不进入 `eval`、反引号或未引用的 `$()`。
- 批量文件使用 `find ... -print0` 配合能处理 NUL 的工具，不解析 `ls` 输出。

### 5.2 破坏性目标清单

删除、改权限或批量替换必须拆成两阶段：

1. `[R0/R1]` 生成目标清单，显示数量、总大小、最老/最新时间、挂载点和抽样路径。
2. 用户审阅并确认精确范围后，才给出或执行 `[R3]` 变更命令。

不得把查找与删除写在同一条命令里，例如未经审阅的 `find ... -delete` 或 `find ... -exec rm`。

### 5.3 下载与脚本

- 禁止 `curl ... | sh`。应下载到受限临时目录，核对来源、TLS、签名或校验和，人工审阅，再按授权执行。
- 不运行 base64 解码后不可见的命令、来自日志/issue/网页的未知脚本或临时获得的闭源二进制。
- 临时脚本必须有明确输入、错误处理、dry-run、日志、退出条件和清理方式；生产批量执行前先 canary。

## 6. 敏感信息处理

- 展示配置时只提取必要键，使用 `sed`/`grep` 也要防止把邻近秘密带出。
- 日志示例中对 token、Cookie、邮箱、IP、用户标识按任务需要脱敏。
- 临时抓包、dump、备份文件使用 `umask 077` 和受控目录，说明保留期限和删除责任人。
- 不把 secret 作为命令行参数；优先受权限保护的文件描述符、环境注入工具或交互输入，但不要在聊天中收集 secret。
- 发现凭据疑似泄露时停止扩散内容，记录凭据类型和影响范围，建议由凭据所有者轮换。

## 7. 批量与自动化

- 明确主机清单来源、数量、环境和排除项，拒绝对动态全量清单直接写操作。
- 先 1 台 canary，再小批次，再扩大；每批设置失败阈值和自动停止条件。
- 限制并发、连接超时和单机超时，避免同时重启、缓存击穿或控制面过载。
- 结果必须按主机记录成功、失败、未执行和未知，不能用整体成功掩盖部分失败。
- R3 操作不要在无人值守循环中无限重试；重复操作可能加重数据损坏或中断。

## 8. 变更确认模板

```text
目标：<environment>/<host>/<service-or-path>
动作：<exact action>
风险：R2/R3；<expected impact and worst case>
预检：<facts already verified>
回滚：<exact rollback and trigger>
验证：<technical and business health checks>
请确认：是否允许执行以上单一步骤？
```
