# Linux 主机安全事件响应

本文用于疑似入侵、恶意进程、异常登录、凭据泄露、勒索、挖矿、WebShell、rootkit 或日志篡改。核心原则是：先保护人员和关键业务、限制扩散、保留证据，再根除和恢复。

Agent 不能代替组织的安全事件负责人、法务、隐私、取证或业务决策。涉及监管、个人数据、支付或重大生产影响时立即升级。

## 1. 识别事件并停止常规修复

以下信号应切换到事件响应模式：

- 未知管理员账户、SSH key、sudo 规则、timer/cron 或 systemd service。
- 无法解释的外连、监听、隧道、挖矿负载或安全工具告警。
- 登录来源异常、凭据在日志/代码/公开渠道出现。
- 文件批量加密/改名、勒索信、备份异常删除。
- 日志空洞、时间戳异常、安全服务停用、系统二进制摘要异常。
- 同类 IOC 出现在多台主机。

不要先重启、删除文件、kill 进程、清日志、重装或轮换所有东西；这些动作会丢失易失证据、触发攻击者或扩大中断。

## 2. 立即确认的决策信息

- 哪些主机、账户、业务、数据和环境可能受影响。
- 事件是否仍在进行，是否有数据破坏/外传或横向移动风险。
- 当前主机是否承担关键业务、集群 quorum、认证、备份或安全控制。
- 谁是事件负责人，谁有权决定隔离、中断、凭据轮换和客户/监管通知。
- 时间源是否可靠，所有记录使用哪个时区。

如果存在人身安全、关键基础设施或正在进行的大规模数据破坏，按组织紧急流程立刻升级，不等待完整诊断。

## 3. 证据保护边界

- 所有检查记录 UTC/带 offset 时间、目标、操作者、命令和输出位置。
- 原始证据只读保存，计算摘要；分析副本与原件分离。
- 文件、抓包、内存或磁盘镜像需要受控存储、最小权限、加密传输和 chain of custody。
- 不修改可疑文件的时间戳、权限或内容；不执行可疑二进制来“看看做什么”。
- 不把敏感证据、完整 IOC 数据、个人信息或 secret 贴入聊天。
- 怀疑内核级入侵时，本机命令输出可能不可信；由取证人员从可信介质/外部平台采集。

## 4. 最小易失信息采集

以下为 `[R1]`：可能暴露敏感元数据并改变少量访问时间/缓存。只在事件负责人允许、目标明确时采集到受限位置。

```bash
# [R1] 基本时间、身份、启动和会话。
date -Is
hostnamectl 2>/dev/null || hostname
uptime
who -a
w
last -Fai | head -n 100
```

```bash
# [R1] 进程、网络和服务快照；输出应受控保存并脱敏分享。
ps -eo user,pid,ppid,lstart,stat,%cpu,%mem,cmd --forest
ss -plantue
systemctl list-units --type=service --state=running --no-pager
systemctl list-timers --all --no-pager
```

```bash
# [R1] 近期高优先级与认证线索，按已知时间窗收窄。
journalctl --since '<start-time>' --until '<end-time>' -p notice..alert --no-pager -o short-iso
journalctl -u sshd -u ssh -u sudo --since '<start-time>' --until '<end-time>' --no-pager -o short-iso
```

不要无边界遍历全盘或哈希全部文件；这会产生大量 IO、改变 atime 并拖慢生产。由 IOC、时间窗和关键路径逐步缩小。

## 5. 持久化与身份检查

只读盘点范围：

- 本地/NSS 账户、组、sudoers、authorized_keys。
- systemd system/user units、timer、cron、at、启动脚本。
- 容器、镜像、挂载、未知 package/repository。
- shell profile、动态链接 preload、内核模块和安全工具状态。

发现未知项时记录：路径、inode、属主、权限、时间戳、摘要、进程/网络关联和权威配置来源。不要立即 disable/delete；先判断其证据价值和隔离影响。

## 6. 隔离与遏制

隔离主机、封禁地址、停止进程/服务、锁账户、撤销 token、断开网络或摘除流量均可能中断业务，属于 R3，需要事件负责人和相应业务/网络授权。

选择遏制方式时权衡：

- 攻击仍在进行和外传风险。
- 关键业务可用性与人身/监管影响。
- 是否需要保留内存、网络连接和攻击者行为证据。
- 隔离是否会破坏 quorum、备份、身份或管理通道。
- 是否有 EDR、交换机、云安全组、LB 或账号控制面等更可靠的外部隔离点。

通常优先在外部控制面进行精确隔离并保留取证管理通道。不要用 flush 防火墙、关闭全部网络或立即关机作为默认动作。

如果不具备授权，只提供具体影响、选项和推荐决策，不自行隔离。

## 7. 凭据泄露

处理顺序：

1. 停止继续展示或复制 secret，确认凭据类型、所有者、权限和暴露时间窗。
2. 识别使用该凭据的服务、主机、自动化和衍生凭据。
3. 由凭据所有者撤销/轮换；优先短期、最小范围的新凭据。
4. 更新依赖并验证，再撤销旧值，避免无计划轮换导致大面积中断。
5. 检查暴露窗口内的访问与异常使用。
6. 从日志、history、工件、缓存和版本历史移除副本需按证据/合规要求进行，不能先毁证。

Agent 不收集新旧 secret 的明文。报告使用 ID、fingerprint、scope 和状态，不显示值。

## 8. 根除

根除必须建立在影响范围和入口已较清楚之后：

- 删除恶意文件/账户、修漏洞、关闭入口、轮换凭据和重建系统都是变更，逐项授权与记录。
- 高权限或内核级 compromise 不应仅“删进程”；优先从可信镜像重建并恢复经验证的数据。
- 不能证明系统完整性时，不把清理后的原机直接重新投入生产。
- 修补入口前保留必要证据；修补后检查同 IOC 的其他主机和身份。
- 不运行未知“查杀脚本”或从互联网复制的清理命令。

## 9. 恢复

恢复遵循 `backup-and-recovery.md` 和 `change-and-rollback.md`：

- 使用可信介质、已验证镜像和不早于安全恢复点的干净数据。
- 在隔离网络验证补丁、配置、账户、日志、安全工具和业务功能。
- 分批恢复流量，监控原 IOC、外连、认证、完整性和业务指标。
- 旧系统和证据按保留策略隔离，不立即销毁。
- 进入生产前由事件负责人和业务负责人共同确认残余风险。

## 10. 事件报告

至少包含：

- 事件编号、级别、负责人、目标与时间线。
- 已确认事实、未证实假设和证据来源。
- 受影响的主机、账户、数据、业务和时间范围。
- 遏制、根除、恢复动作及授权者、执行者、时间和结果。
- 凭据、备份、日志、检测和通知状态。
- 残余风险、继续观察的 IOC/指标和后续责任人。

未确定根因或影响范围时明确写“未知”，不要为了结案给出无证据结论。

## 11. 必须人工升级的情况

- 涉及 root、内核、hypervisor、身份系统、备份系统或多个生产环境。
- 可能存在个人数据/支付数据/商业秘密外泄或监管通知义务。
- 勒索、破坏仍在进行，或攻击者拥有持续控制。
- 证据可能用于法律、保险或纪律程序。
- 需要大范围隔离、关机、密钥轮换、客户通知或灾难恢复。
- 本机工具/日志可能不可信，或 Agent 无法确保操作不破坏证据。
